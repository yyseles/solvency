数据口径、分析方法与更新机制

  • 平台范围：保险行业四个板块——保险集团控股公司、财产保险公司、人身保险公司、再保险公司，分别来自四个独立数据源文件，各板块公司集合与期间覆盖相互独立。
  • 口径归一（重要）：每年含 Q1–Q3、Q4（审计前/预披露）、年度（审计后/经审计）。本平台统一采用「年末优先取年度（审计后），无年度则取 Q4（审计前）」的归一化口径，每个公司每个年度只保留一个年末值；季度取 Q1/Q2/Q3。因此不再需要区分双口径切换。
  • 单位：除充足率（比率，显示时×100 为 %）外，所有资本/资产/负债指标单位均为人民币万元；图表中金额统一折算为亿元展示。
  • 监管红线：综合偿付能力充足率 ≥ 100%、核心 ≥ 50% 方为达标；任一不达标即列为风险公司。"关注"定义为综合 100–120% 或 核心 50–60%。
  • 行业聚合：充足率类指标按公司中位数/均值统计（不加权，避免大公司主导）；金额类指标（实际资本、最低资本等）按公司求和得行业合计。概览与趋势另提供监管口径加权平均：综合 = Σ实际资本 / Σ最低资本，核心 = Σ(核心一级＋核心二级) / Σ最低资本，即监管意义上的行业整体充足率（受大公司主导，与中位数互补）；综合与核心两项加权均只纳入「实际资本、核心一级、核心二级、最低资本四项齐全」的公司，以保证同一群体下 综合 ≥ 核心 恒等式成立。
    未披露（空值）处理：某期末综合/核心充足率为空（NaN/缺失）的公司，状态标记为「未披露」，表示当期未披露偿付能力数据（多为被接管/风险处置类机构），该状态单列——既非达标也非不达标，不计入达标率分母、也不计入风险公司数。「风险分布」另设「未披露」分段以单独呈现。
  • 最低资本风险结构（产/寿/再保）：基于各板块《最低资本》明细表（C-ROSS 二期标准 33 项），对量化风险最低资本进一步下钻——寿险/非寿险业务保险风险、市场风险、信用风险的子项（如寿险的损失发生/退保/费用风险，市场的利率/权益/房地产/汇率风险，信用的利差/交易对手违约风险等），以及附加资本（逆周期、D-SII、G-SII、其他）构成；可叠加「行业合计」对比。明细数据年末值取自各年第4季度（审计前）披露，与主表年末（审计后）口径略有差异，均同源季度披露。保险集团因成员公司资本明细未披露、且无集团特有风险最低资本，该下钻分析暂缺。
  • 指标关系（校验用）：最低资本 N ≈ 量化风险最低资本 O ＋ 控制风险最低资本 V；实际资本 I ＝ 核心一级 J ＋ 核心二级 K ＋ 附属一级 L ＋ 附属二级 M。
  • 缺失字段：W/X/Y/Z（保险/银行/证券/信托类成员公司最低资本）原表全空，已剔除；核心二级资本(K)、附属二级资本(M) 部分公司早期缺失。
  • 后续更新：页面顶部「数据」按钮提供自助更新——导出当前数据为 JSON、改好数值后导入即刷新、再「导出可转发网页」生成新单文件转发（无需服务器）。也可把 xlsx/JSON 发我代更新。以相同格式的 xlsx 上传时两种模式：
    ① 补充/修正（append，upsert）——新文件里出现的「公司×期间」记录会覆盖已有并补充新增，其余记录保持不变。因此修正某条上传错误：只需用 append 模式上传仅含该条（或含该条）记录的文件即可，不会动到其它数据；新增一个季度同理。
    ② 整段替换（replace）——该板块整体由新文件替换（旧记录全部丢弃）。
    运行：
    python tools/data_pipeline.py update --segment life --xlsx 寿险偿付能力.xlsx --mode append（修正/补充）
    python tools/data_pipeline.py update --segment life --xlsx 寿险偿付能力.xlsx --mode replace（整段替换）
    （segment 取 group / property / life / reins），刷新页面即生效。
  • 数据来源：各公司偿付能力季度报告摘要（公开披露），由精算整理。

数据管理

导出当前数据备份；导入你更新后的 JSON 即可刷新全部图表；"导出可转发网页"会把当前数据重新打包进单文件，可直接转发给别人（无需服务器）。

怎么更新数据：
① 点「导出数据(JSON)」得到 solvency_data.json（含各家保险公司明细 + 监管披露行业平均数）；
② 用编辑器/Excel 改好里面的数值后，点「导入数据(JSON)」上传，页面立即刷新；
③ 点「导出可转发网页」生成新的单文件，发给大家即可。
